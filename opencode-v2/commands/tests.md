Write the missing tests of the code the request names, with their proof, in this single run, without a ticket: no ticket sheet, no Jira call, no merge request. The developer is here for /tests: its wizards are the question calls this procedure names (each one ONE question tool call, its questions together), and its « Suite » at the end; never another question. The test-guardian writes and proves the tests; you never write a test yourself. A question call of a wizard never has the header « Suite »: only the last question of the run does.

## 0. The mode
From the line « Mode : » of the facts:
- `menu` (nothing after /tests): section M.
- `env-launch` (`/tests env` alone): section L. `env-config` (`/tests env config [<environnement>]`): section C. `env` (`/tests env <environnement> …`): section E.
- `api` (`/tests api …`): section A.
- `unit`: the unit tests, steps 1 to 4.

## M. The menu
Nothing is written. The answer, in French: header « **/tests** — que tester ici ? », then the line « ✅ <in one sentence: the API and its endpoints, the environments, the files without tests the facts list> » (this run ends at its « Suite » question: its final answer carries the mark), then one line per option below. Then ONE question tool call, header « Suite », the recommended option first with « (recommandé) »:
- each file of « Candidats aux tests unitaires » (3 at most): label « /tests <file> », description « tests unitaires du comportement actuel de <class> (modifié <n> fois récemment, aucun test ne le nomme) »;
- with an ASP.NET Core API: « /tests api » (« ses <n> endpoints, scénario par scénario, en mémoire ; et leurs tests d'environnement »);
- each environment that is not production, when there are environment tests (2 at most): « /tests env <name> » (« ses tests d'environnement, en lecture seule »);
- « /tests env config » (« déclarer un environnement : son URL, son OIDC (client id, secret), son proxy, son certificat ; puis l'accès vérifié »), recommended when the API has no environment;
- « Rien pour l'instant » (« ou tape /tests <une classe> pour une autre »).

Never stop on a variable the facts say « not set »: they saw the environment of OpenCode when it started (a service may see none), while each command reads `~/.zshenv` again; env-tests.sh says it, with its `export` line, when one is really missing.

## C. The configuration wizard (`/tests env config [<environnement>]`)
It writes the block of one environment in AGENTS.md « ## Environnements », through `env-setup.sh` only (never the edit tool, never a secret: only the names of the variables of this machine, by convention <NAME>_CLIENT_ID, <NAME>_CLIENT_SECRET, <NAME>_PROXY_CREDENTIALS, API_TOKEN_<NAME>), then checks the access. Nothing is committed: AGENTS.md goes with /push.
1. ONE question tool call (step 1 of 2), its questions together, each option's description saying what it writes:
   - header « Nom », only when the request names none: the names of « HINT URL » not declared yet (the first recommended), « Modifier <name> » for each declared one; the developer may type another (letters, digits, - : `recette`, `preprod`).
   - header « URL »: the URLs of « HINT URL » (the one of the same name recommended), the current URL of an environment modified; or typed (the base URL of the API there, without user or password).
   - header « Accès »: « OIDC client credentials (recommandé) » (« un jeton demandé à son fournisseur à chaque run : client id, secret dans une variable, scope »: recommended when the facts show a HINT OIDC or HINT AUTHORITY or an AUTHENTICATION by JWT), « Jeton fixe dans une variable » (« API_TOKEN_<NAME> : un jeton de service qui n'expire pas »), « Aucun » (« une API ouverte »).
   - header « Proxy »: « Celui de cette machine » (« <the host of PROXY OF THIS MACHINE, never its credentials> », recommended when there is one), « Aucun » (« accès direct, même si la machine a un proxy »), and the developer may type the URL of another proxy (`http://<hôte>:<port>`, without credentials).
   - header « Identifiants », only with a proxy: « Non (recommandé) », « Oui : <NAME>_PROXY_CREDENTIALS » (« utilisateur:mot de passe dans cette variable de ~/.zshenv »).
   - header « Usage »: « Lecture seule (recommandé) », « Écriture permise » (« les tests EnvironmentWrites pourront y créer puis supprimer leurs données »), « Production » (« jamais testée : seule sa ligne est écrite »).
2. Only for « OIDC client credentials » (never for production): ONE question tool call (step 2 of 2), together:
   - header « Autorité »: « HINT AUTHORITY » and the « Authority » of « HINT OIDC » (recommended), or typed (Keycloak: `https://<hôte>/realms/<realm>`; Entra ID: `https://login.microsoftonline.com/<tenant>/v2.0`).
   - header « Client id »: « Dans la variable <NAME>_CLIENT_ID (recommandé) », or the client id typed (written in AGENTS.md: an identifier, not a secret).
   - header « Scope »: « HINT SCOPE » (recommended: Entra ID asks `api://<application>/.default`), « Aucun scope » (Keycloak, an audience given by the client itself), or typed (several separated by spaces).
   - header « Certificat »: « Aucun (recommandé) », or typed (the PEM file of the internal certificate authorities, `~/…` allowed: a proxy that re-signs TLS, an internal certificate).
   - header « Avancé », `multiple: true`: « Rien de plus (recommandé) », « Le client s'authentifie en Basic » (client_secret_basic); the developer may type `audience=<value>` or `resource=<value>` (Auth0, ADFS).
3. ONE shell call: `sh ~/.config/opencode/scripts/env-setup.sh set <name> --url <url> [--oidc <authority>] [--client <id> | --client-var] [--scope "<scopes>"] [--audience <a>] [--resource <r>] [--auth-client basic] [--token-var] [--proxy none | --proxy <url> [--proxy-auth]] [--ca <file>] [--health <the « Santé » path of the facts>] [--writes | --production] ; sh ~/.config/opencode/scripts/env-tests.sh --check <name>` (the check runs even when the block was not written: its STOP says why); no check for production. A "STOP:" line of env-setup.sh: answer with it; nothing was written.
4. The answer, in French: header « **/tests env config** — <name> », then « ✅ Accès vérifié » when the check ends with « CHECK: OK », otherwise « ⛔ <its ENVIRONMENT PROBLEM in one French sentence> » (a variable not set right after the first configuration is expected: say it simply); the block written (a code block, as env-setup.sh printed it), the variables to put in `~/.zshenv` (its `export` lines, never a value), and a table | Étape | Résultat | from the CHECK lines (variables, proxy, discovery, token: its audience, its client, its scopes and roles; the API with and without the token). Last, the « Suite » question: « /tests env <name> » (recommended when the check passed and environment tests exist), « /tests api » (« écrire les tests d'environnement de ses endpoints », when there are none), « /tests env config <name> » (« revérifier l'accès », recommended when the check failed), « /push » (« AGENTS.md dans un commit, avec une MR »), « Rien pour l'instant ».

## E. The environment tests on an environment (`/tests env <environnement> …`)
Nothing is written, committed or pushed. A scheduled run comes here (its environment is always named): never a question before its « Suite ».
1. ONE shell call: `sh ~/.config/opencode/scripts/env-tests.sh <the environment> [--ecriture, only when the request says « --écriture » or « écriture »] [--filter "FullyQualifiedName~<word>|FullyQualifiedName~<word>", from the other words of the request: classes or tests]`. It checks the access first (variables, proxy, certificate, the OpenID Connect provider and its token, the API), builds the test project, then runs the tests marked Environment against the URL AGENTS.md gives, with the token of this run: never set a URL, a token or a variable yourself, never call the API yourself (curl, a script). A "STOP:" or "ENVIRONMENT PROBLEM:" line: stop with it in one French sentence (a variable not set, a proxy or a provider that refuses, an environment out of reach are the developer's to fix, never retried another way), and the « Suite » offers « /tests env config <environment> (recommandé) » (« vérifier et corriger l'accès pas à pas »).
2. The answer, in French: header « **/tests env** — <environment> (<URL>) », then « ✅ <n> tests passés » or « ⛔ <k> en échec sur <n> », how it was reached (« jeton OIDC de <provider>, proxy <host> », from its ENVIRONMENT line), a table | Test | Résultat | Durée | from its lines « OK » and « FAILED », and for each failure its message (the status received, what was expected). A failure on an environment is a fact about that deployment (its version, its configuration, its data): say which, never a fix. Last, the « Suite » question: « Rien pour l'instant (recommandé) », « /tests env <the same environment> » (« relancer plus tard »).
