# /outil http

Started directly as the command `/pack-http` (this procedure is the message that started you, with no line « Skill : pack-http » printed before it): answer only « Lance `/outil http` : cette procédure a besoin de ce que /outil prépare. » and stop.

The pack already ran `http-files.sh --plan` (the lines above): nothing is written yet. PLAN (the folder of the files), GROUP (each controller or file of minimal APIs, its requests, and whether its file exists), ENVIRONMENT (local, then those of AGENTS.md but production: how each gets its token, and where its secret is: a variable of this machine or HashiCorp Vault), FILE (the files that exist), NOTE, GROUPS (their names). A "STOP:" line: answer with it and stop.

1. ONE question tool call (the wizard, one step), its questions together:
   - header « Contrôleurs », `multiple: true`: « Pour quels contrôleurs j'écris les requêtes ? », « Tous (recommandé) » then one option per GROUP (label its name, description its requests and its file).
   - header « Client »: « Rider (recommandé) » (« le jeton de chaque environnement OIDC demandé par Rider lui-même : OAuth 2.0 client credentials, renouvelé tout seul ; ailleurs, un jeton à coller ; tes secrets dans http-client.private.env.json »), « Visual Studio » (« un jeton à coller par environnement, dans http-client.env.json.user : Visual Studio ne lit ni la configuration OAuth de Rider ni son fichier privé »).
   - header « Existants », only when a GROUP or a FILE says « exists »: « Garder (recommandé) » (« tes requêtes modifiées restent telles quelles »), « Remplacer » (« les fichiers .http choisis et http-client.env.json réécrits ; jamais le fichier privé »).
   - header « Secrets », only when an ENVIRONMENT line says where a secret is (« --private fills it »): « Les remplir depuis ~/.zshenv et Vault (recommandé) » (« le secret client et les jetons, depuis les variables et Vault qu'AGENTS.md nomme : jamais affichés, jamais commités, jamais lus par un agent »), « Je les colle moi-même ».
2. ONE shell call: `sh ~/.config/opencode/scripts/http-files.sh [--only <the groups, separated by commas, when not all>] [--replace] [--client vs] [<the folder of the arguments>]`, followed, with « Les remplir », by ` && sh ~/.config/opencode/scripts/http-files.sh --private [<the same folder>]`. Its FILLED lines name what was filled, never a value; its EMPTY lines what stays to paste and why.
3. The bodies: each request with a line « # body: <Type>, to fill in » has `{}` as its body. Find each type in one turn of searches (grep tool on `record <Type>` and `class <Type>`), then replace each `{}` with one JSON object: the properties of the type in camelCase (or the naming of the repository's JSON options), realistic values that pass its validation (its attributes, its validator), never a real person, e-mail or secret. A type found nowhere: leave `{}` and say it.
4. Never open, read or write `http-client.private.env.json` nor `http-client.env.json.user`, never run `vault`: the secrets go there by `http-files.sh --private` or by the developer's hand (your rules refuse them anyway).
5. The answer, in French: the files written or kept, the bodies filled, the secrets filled (the FILLED lines: environment, key, from where) and what stays to paste (the EMPTY lines), then how to use them: open a `.http` file in Rider, pick the environment at the top of the editor (`local`, then those of AGENTS.md; production is never there), run one request or all of them (Rider checks the status of each). For an OIDC environment with Rider, the first request asks the token itself (client credentials of its provider, through the proxy of Rider's settings: Settings > Appearance & Behavior > System Settings > HTTP Proxy). Visual Studio: the token of each environment in `http-client.env.json.user` (it cannot ask an OIDC token: a fresh one to paste, or Rider). Both private files are ignored by git (the line was added to `.gitignore` when it was missing) and never pushed (the check before the push refuses them); the route values (`id`…) are in `http-client.env.json`; each NOTE line (a token URL to fill in). A secret that changed in Vault or in ~/.zshenv: empty its value, then `/outil http` again (a value already there is never replaced). Last, the « Suite » question: « /push (recommandé) » (« les fichiers .http et le .gitignore partent dans un commit, jamais les fichiers privés »), « /tests env config <environment> » when a NOTE says its token URL is missing or an EMPTY line says where its secret is not given (« le lire chez son fournisseur, dire où est son secret »), « Rien pour l'instant ».
