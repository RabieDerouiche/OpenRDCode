# /outil http

Started directly as the command `/pack-http` (this procedure is the message that started you, with no line « Skill : pack-http » printed before it): answer only « Lance `/outil http` : cette procédure a besoin de ce que /outil prépare. » and stop.

The pack already ran `http-files.sh --plan` (the lines above): nothing is written yet. PLAN (the folder of the files), GROUP (each controller or file of minimal APIs, its requests, and whether its file exists), ENVIRONMENT (local, then those of AGENTS.md but production: how each gets its token), FILE (the environment files that exist), NOTE, GROUPS (their names). A "STOP:" line: answer with it and stop.

1. ONE question tool call (the wizard, one step), its questions together:
   - header « Contrôleurs », `multiple: true`: « Pour quels contrôleurs j'écris les requêtes ? », « Tous (recommandé) » then one option per GROUP (label its name, description its requests and its file).
   - header « Client »: « Rider (recommandé) » (« le jeton de chaque environnement OIDC demandé par Rider lui-même : OAuth 2.0 client credentials, renouvelé tout seul ; ailleurs, un jeton à coller »), « Visual Studio » (« un jeton à coller par environnement : Visual Studio ne lit pas la configuration OAuth de Rider »).
   - header « Existants », only when a GROUP or a FILE says « exists »: « Garder (recommandé) » (« tes requêtes modifiées restent telles quelles »), « Remplacer » (« les fichiers .http choisis et http-client.env.json réécrits ; jamais le fichier privé »).
2. ONE shell call: `sh ~/.config/opencode/scripts/http-files.sh [--only <the groups, separated by commas, when not all>] [--replace] [--client vs] [<the folder of the arguments>]`.
3. The bodies: each request with a line « # body: <Type>, to fill in » has `{}` as its body. Find each type in one turn of searches (grep tool on `record <Type>` and `class <Type>`), then replace each `{}` with one JSON object: the properties of the type in camelCase (or the naming of the repository's JSON options), realistic values that pass its validation (its attributes, its validator), never a real person, e-mail or secret. A type found nowhere: leave `{}` and say it.
4. Never open, read or write `http-client.private.env.json`: the developer's secrets go there, by hand.
5. The answer, in French: the files written or kept, the bodies filled, then how to use them: open a `.http` file in Rider, pick the environment at the top of the editor (`local`, then those of AGENTS.md; production is never there), run one request or all of them (each checks its status). For an OIDC environment with Rider, the first request asks the token itself (client credentials of its provider, through the proxy of Rider's settings: Settings > Appearance & Behavior > System Settings > HTTP Proxy); what each environment needs in `http-client.private.env.json` (its PRIVATE line: the client secret, a token, the client id when AGENTS.md keeps it in a variable), once, never committed (ignored by git: the line was added to `.gitignore` when it was missing); the route values (`id`…) in `http-client.env.json`; each NOTE line (a token URL to fill in). Last, the « Suite » question: « /push (recommandé) » (« les fichiers .http et le .gitignore partent dans un commit »), « /tests env config <environment> » when a NOTE says its token URL is missing (« la lire chez son fournisseur et l'écrire dans AGENTS.md »), « Rien pour l'instant ».
